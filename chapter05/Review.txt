[9] According to the outline in the chapter, describe the differnce between a Term, and Experession
a number, and a primary.

Number: A number is a leaf node or taken in the grammar. 
A floating-point or integer literal a Token.

Primary: A primary is a build block for the evaluation, 
where parentheses is the highest level. Primary either 
a raw number of floating-point literal or a full expression 
wrapped in parentheses.

Term: A higher-precedence sub-component of an Expression. 
A Term consists of Primaries combined by multiplication 
(*) or division (/) operators.

Expression: The top-level grammatical construct representing full calculations. 
An Expression consists of Terms combined by addition (+) or subtraction (-) operators.

1. Structure Breakdown 
    1.25: A Number, which forms a Primary, which forms a Term, 
    which acts as the left-hand side of the outer Expression.

    2 * 3: A Term composed of two Primaries (2 and 3) joined by a multiplication operator.

    (2*3): A Primary! Wrapping the expression 2 * 3 in parentheses turns the entire inner 
    calculation back into a single Primary token for the outer calculation. 

    1.25 + (2 * 3): The full Expression, taking the Term 1.25 and adding the Term (2 * 3).

    Literals: Numeric values like 3.14 or 17 (stored with a value).

[14] What is a class? What do we use classes for? 
A class is a core feature in C++ used to create user-defined data types. 
Classes allow custom types to behave similarly to built-in (primitive) 
types like int or double.

We use classes to: 
Bundle Data & Behavior: Group data members (variables) and member functions 
(methods) into a single entity.

Control Access (Encapsulation): Hide internal state using private members 
while exposing a controlled interface using public members.

Define Custom Operations: Overload operators (e.g., +, ==, <<) and provide 
functions to perform operations specific to the custom data type.

[15] How can we provide a default value for a member of a class? 
In C++, there are two primary ways to provide default values for class members:

    1. In-Class Member Initializers: Provide a default value directly at the variable 
    declaration inside the class definition using = or {}.
    class Token {
        char kind = ' ';     // Default value provided directly
        double value = 0.0;
    };

    2. Constructor Initializer Lists: Define default values inside constructors, 
    or accept arguments to initialize members dynamically when an object is created.
    class Token {
            char kind;
            double value;
        public:
            Token() : kind(' '), value(0.0) {} // Default constructor
            Token(char k, double v) : kind(k), value(v) {} // Parameterized constructor
    };


[16] In the expression function, why is the default for the switch-statement to “put back” the token? 
    The expression() function handles addition (+) and subtraction (-). 
    After reading a Term, it fetches the next token to check if an operator follows:
    If it receives + or -: It consumes the operator and evaluates the next Term. 
    If it receives anything else (default case): It means the current expression 
    calculation is complete (e.g., encountered a ';' print command, ) closing parenthesis, 
    or end-of-input ')'. 
    Because expression() peeked at that token and realized it isn't + or -, 
    it must use ts.putback(t) to return the token to the Token_stream. This ensures whatever 
    function called expression() or the main execution loop can read and handle that token 
    correctly otherwise it will disappeare.

[17] What is “look-ahead”? 
    Look-ahead is a parser mechanism where the parser reads one or more upcoming tokens 
    from the input stream before deciding which grammar rule or action to execute, 
    without permanently consuming those tokens.

[18] What does putback() do and why is it useful? 
    putback() is a method on a Token_stream that returns a previously read token back into 
    the stream buffer so it can be re-read by the next get() call.

    it usefull because, it enables 1-token look-ahead in recursive descent parsers. 
    Since a parser can only decide which grammar branch to take by inspecting incoming tokens, 
    putback() lets it "peek" into the future without consuming or destroying input tokens that 
    other functions need.

[19] Why is the remainder (modulus) operation, %, difficult to implement in the term()? 
    The remainder operator % is difficult to implement in term() because the calculator's 
    grammar uses double (floating-point) types for numeric evaluations, whereas the 
    standard C++ % operator is strictly defined for integer types (int).

[21] Why do we (sometimes) split a class’s members into private and public members? 
    We split a class's members into private and public to enforce encapsulation and 
    data abstraction. This separation creates a clear distinction between how a class 
    is used versus how it works under the hood.

    As long as the public interface remains unchanged, you can modify, optimize, or 
    completely rewrite the private internal implementation without breaking any 
    existing code that depends on the class.

[22] What happens in the Token_stream class when there is a token in the buffer 
and the get() function is called? 
    When get() is called while a token is present in the buffer, the function performs 
    three specific actions:

    Returns the buffered token: It retrieves the Token currently stored in the internal 
    buffer variable rather than reading a new character from standard input (cin).

    Clears the buffer flag: It sets the full boolean flag to false to indicate that the 
    buffer is now empty.

    return the token value: It returns that retrieved Token directly back to the 
    caller (e.g., primary(), term(), or expression()).

[25] What is a “user-defined type”? Why would we want one? 
    A user-defined type is a custom data type created by the programmer 
    (using constructs like class or struct in C++) rather than one built 
    directly into the language syntax (like int, double, or char).

    Domain Modeling: Built-in types like double or int carry no domain context. 
    Creating custom types like Token, Vector, or Date allows code to directly 
    reflect real-world or problem-specific concepts.

    Encapsulation & Safety: Grouping related data members and member functions 
    into a single type ensures that data cannot be easily corrupted or placed 
    in an invalid state by outside code.

    Abstraction & Code Reuse: A user-defined type hides complex implementation 
    details behind a clean, simple public interface, making code easier to read, 
    maintain, and reuse across different parts of a program.
