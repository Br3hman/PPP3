[1] What is the difference between a declaration and a definition?
    For Function and class:
        Declaration: Tells the compiler the name, return type, and parameters
        of a function (or the structural layout of a class) so we can use it
        before its implementation. It requires no memory for function execution logic.
            Example: void printMessage();
        Definition: Provides the actual body of the function.
            Example: void printMessage() { std::cout << "Hello"; }

    Variable:
        To write a pure declaration for a variable (one that allocates no memory),
        we must use the extern keyword. This tells the compiler, "This variable exists,
        but its memory is already allocated somewhere else."
        Writing int x; (without assigning a value) still allocates memory immediately.
        The compiler reserves 4 bytes on the stack right away;
        x just holds garbage data until you assign a value.

[12] What is the difference between a class scope and local scope?
    1. Class Scope
    Visibility: Members (variables and functions) declared inside
    a class or struct are visible to all methods throughout the entire class,
    regardless of the order they are written.
    Unique Feature (Order-Independent): Unlike local scope, a member function can

    Lifetime: Class variables exist as long as the object instance exists in memory.

    2. Local Scope (Block Scope)
    Visibility: Names declared inside a set of curly braces { }

    declaration down to the closing brace}.
    Strict Top-to-Bottom: You cannot access a local variable before the exact line it is declared.
    Lifetime: Local variables are created when execution enters the block
    { and destroyed immediately when execution exits the block }.

[13] Why should a programmer minimize the number of global variables?
    Minimizing global variables is a fundamental principle of writing clean,
    maintainable software.
    Here are the main reasons why reliance on global variables should be avoided:
    1. Harder to Debug and Trace State
        Because any function anywhere in your program can modify a global variable,
        it becomes extremely difficult to track down where and when a value was unexpectedly changed.
        You lose control over the variable's state history.

    2. Risk of Name Collisions
        As projects grow larger or integrate third-party libraries, using global variables increases
        the chance that two separate parts of the codebase will accidentally use the same variable name,
        leading to unexpected compilation errors or logic bugs.

    3. Tight Coupling and Poor Reusability
        Functions that rely on global variables cannot be easily taken out of one project and reused in another.
        They depend on hidden external dependencies rather than taking explicit inputs through their parameter lists.

    4. Breaks Thread Safety (Concurrency Issues)
        In modern multi-threaded programs, if multiple threads attempt to read and write to the same global
        variable simultaneously without complex locking mechanisms, it leads to race conditions and
        unpredictable memory corruption.

    5. Hidden Data Dependencies
        When a function takes arguments, its inputs are clear and self-documenting.
        When a function silently modifies global variables, its behavior becomes opaque,
        making the code harder for other programmers to read and test reliably.

[18] Give an example of undefined order of evaluation. Why can undefined order of evaluation be a problem?
    when an expression or function call has multiple subexpressions, the compiler is allowed to execute
    them in whatever order it chooses.when multiple subexpression or function

    void printTwo(int a, int b) { /* ... */ }
    int i = 0;
    printTwo(i++, i++); // UNDEFINED ORDER OF EVALUATION!

    int x = 10;
    int result = x + ++x; // Problem! Does it read 'x' before or after incrementing?

    Key Exceptions (Guaranteed Order)
    Order of evaluation is not left-to-right for most operations, with a few strict exceptions:
        Logical Operators (&& and ||): Guaranteed left-to-right with short-circuiting.
        Comma Operator (,): Guaranteed left-to-right (expr1 , expr2).
        Ternary Operator (? :): Evaluates the condition first, then only one of the branches.
        C++17 Chain Guarantees: C++17 added stricter rules for expressions like
        a.b(), a << b, and a = b (where b is evaluated before a receives it),
        but function argument ordering remains mostly un-specified.

        Golden Rule: Never modify a variable and read/modify it again within the
        same un-sequenced expression! Break complex statements into multiple lines instead.

[21] What goes into an activation record?
    An activation record (also called a stack frame) is a chunk of memory pushed
    onto the call stack whenever a function is called. It contains:
    -Function Parameters: Input arguments passed to the function.
    -Return Address: Memory address of the instruction to return to after the function finishes.
    -Local Variables: Variables declared inside the function body.
    -Saved Register State / Frame Pointer: Saved CPU registers so the caller's execution state can be restored upon return.

[22] What is a call stack and why do we need one?
    The call stack is a specialized LIFO (Last-In, First-Out)
    memory structure managed by the CPU and OS that tracks active function calls in a executing program.
    It remembers where to return (the return address) when a function finishes executing so control
    returns to the exact line in the caller function.
    The allocates memory dynamically for each function's activation record (local variables, arguments,
    and CPU register states) upon entry and automatically frees it when the function returns.
    It allows functions to call other functions—or call themselves—without overwriting variable values or losing track of the call hierarchy.

[23] What is the purpose of a namespace?
    The primary purpose of a namespace is to prevent name collisions (naming conflicts) in programs
    by grouping related functions, classes, and variables under a distinct scope name.

[24] How does a namespace differ from a class?

    Think of a class as a factory blueprint used to stamp out concrete objects with data
    (member variables) and behavior (member functions).

[25] What is a using declaration?
    using declaration: A using declaration introduces a single specific member
    from a namespace into the current scope.

    Syntax: using [namespace]::[name];

    Example: using std::cout;

    Effect: Now you can type cout directly,
    but for everything else (like std::cin or std::string),
    you still have to write std::.

    using Directive: whereas using Directive (Global/Broad)
    A using directive brings every single name from a
    namespace into the current scope all at once.

    Syntax: using namespace [namespace];

    Example: using namespace std;

    Effect: You can use cout, cin, vector, string, and
    everything else in std without prefixing std::.

[26] Why should you avoid using directives in a header?
    We should avoid placing using directives
    (like using namespace std;) in header (.h or .hpp)
    files primarily because of "namespace pollution" and name collisions.

    *. The Transitive Nature of Header Files: When you #include a header file,
    the preprocessor copies the entire content of that header into the source file
    that included it and into any other header files that include that header.

    If we put using namespace std; inside my_header.h, every single .cpp
    file that includes my_header.h (directly or indirectly) will automatically
    pull the entire std namespace into its global scope.

    The programmer including our header has no choice or control over this behavior.

    names into the global scope creates subtle and dangerous bugs. For example, if you define
    your own custom count function or vector class, and someone includes a header containing

[27] What is namespace std?
    namespace std (short for "standard") is the official
    namespace created by the ISO C++ Standards Committee
    to house all components of the C++ Standard Library.
    Key Concepts
    Purpose: It acts as a container to organize standard functions,
    classes, and objects (like std::cout, std::cin, std::vector, std::string, std::pow)
    and keep them isolated from your own custom code.

    Prevents Name Conflicts: By placing standard features inside std,
    C++ ensures that if you create a function named cout or a class named vector,
    your names won't conflict with the standard library's versions.
